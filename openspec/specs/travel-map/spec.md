# Карта поездок

## Purpose

Показывать географию поездок на интерактивной карте: посещенные страны и регионы, их границы и названия. Спецификация фиксирует существующее поведение приложения.

## Requirements

### Requirement: Интерактивная карта

Приложение SHALL показывать одну карту после готовности Yandex Maps API, с русским интерфейсом, линейкой, поиском и переключением полноэкранного режима. Повторный запуск инициализации на той же странице SHALL NOT создавать вторую карту.

#### Scenario: Открытие приложения

- **WHEN** пользователь открывает приложение и API карты готов
- **THEN** отображается карта с центром в Москве и начальным масштабом 4
- **AND** доступны линейка, поиск и полноэкранный режим

#### Scenario: Повторная инициализация

- **WHEN** инициализация повторяется в рамках той же страницы
- **THEN** остается одна карта без дублирования контролов и объектов

### Requirement: Отображение посещенных территорий

Приложение SHALL отличать посещенные территории зеленой заливкой от непосещенных с серой заливкой. Территория считается посещенной, только если ее код отмечен значением `true`. Страны с региональной детализацией SHALL показывать посещения по регионам, без общей заливки всей страны.

#### Scenario: Страна без региональной детализации

- **WHEN** загружены границы страны, которая не настроена для региональной детализации
- **THEN** ее полигон окрашен в зависимости от отметки посещения страны

#### Scenario: Страна с региональной детализацией

- **WHEN** загружены границы страны, для которой включена региональная детализация
- **THEN** общий полигон страны прозрачен, а заливка каждого региона зависит от отметки посещения этого региона

### Requirement: Подсказки и подсветка границ

Карта SHALL показывать название страны при наведении на страну без региональной детализации. Для региона карта SHALL показывать название страны и региона, выделять границу выбранного региона и более тонко подсвечивать остальные регионы той же группы страны. Группировка регионов SHALL соответствовать действующей конфигурации приложения, включая специальные региональные коды.

#### Scenario: Наведение на страну

- **WHEN** указатель входит в полигон страны без региональной детализации
- **THEN** появляется обводка и доступна подсказка с названием страны
- **AND** при выходе указателя обводка исчезает

#### Scenario: Наведение на регион

- **WHEN** указатель входит в полигон региона
- **THEN** выбранный регион выделяется более толстой обводкой, остальные регионы его группы — более тонкой
- **AND** регионы других групп не подсвечиваются этим наведением
- **AND** при выходе указателя обводка у регионов этой группы исчезает

### Requirement: Работа из подкаталога GitHub Pages

Приложение SHALL работать по пути `/been/` и загружать локальные данные границ относительно базового пути приложения.

#### Scenario: Загрузка опубликованного приложения

- **WHEN** пользователь открывает приложение по пути `/been/`
- **THEN** ресурсы приложения и файлы `countries.json` и `regions.json` запрашиваются внутри этого базового пути

### Requirement: Обновление локальных границ

Приложение SHALL предоставлять браузерную команду `window.downloadBorders()`, которая скачивает границы стран и регионов из Yandex Maps в два JSON-файла для последующего ручного обновления данных репозитория. Координаты в файлах SHALL быть округлены до пяти знаков после запятой без удаления точек, контуров или территорий.

#### Scenario: Скачивание актуальных границ

- **WHEN** после готовности карты разработчик вызывает `window.downloadBorders()` и API успешно возвращает данные
- **THEN** скачиваются `countries.json` с границами стран и `regions.json` с регионами стран, включенных в региональную детализацию
- **AND** данные запрашиваются с качеством 3, а записи в файлах доступны по кодам территорий
- **AND** координаты округлены до пяти знаков, порядок точек и метаданные сохранены

### Requirement: Постепенное отображение карты

Приложение SHALL отображать контейнер карты и включенную статистику без ожидания внешнего API. После готовности API базовая карта и маркеры SHALL становиться доступны без ожидания файлов границ. Страны и регионы SHALL появляться независимо по мере загрузки, с возможностью отрисовки и обработки пользовательского ввода между порциями полигонов.

#### Scenario: Медленный API

- **WHEN** скрипт API еще загружается
- **THEN** контейнер и включенная статистика уже отображаются

#### Scenario: Задержка одного слоя

- **WHEN** один файл границ задерживается, а другой успешно загружен
- **THEN** карта и маркеры доступны, загруженный слой появляется без ожидания задержанного
- **AND** подсказки регионов содержат название страны даже до загрузки слоя стран

#### Scenario: Добавление полигонов

- **WHEN** приложение добавляет загруженные границы
- **THEN** оно предоставляет браузеру возможность отрисовывать карту и обрабатывать ввод между порциями полигонов
- **AND** после завершения доступны все территории и прежняя подсветка групп регионов

### Requirement: Ошибки загрузки карты

Приложение SHALL сообщать пользователю об ошибке загрузки API или слоя границ. Ошибка одного слоя SHALL NOT препятствовать отображению другого слоя, маркеров и доступной базовой карты.

#### Scenario: Ошибка API

- **WHEN** загрузка скрипта API завершается ошибкой
- **THEN** отображается сообщение о невозможности загрузить карту, а статистика сохраняется

#### Scenario: Ошибка слоя

- **WHEN** один из файлов границ недоступен или содержит некорректные данные
- **THEN** отображается сообщение о проблеме с этим слоем
- **AND** другой успешно загруженный слой и маркеры остаются доступны
